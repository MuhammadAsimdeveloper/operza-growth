# OPERZA — ENTERPRISE SECURITY & PLATFORM RISK REGISTER

| Risk ID | Category | Severity | Likelihood | Impact | Description & Attack Vector | Mitigation Strategy | Status |
| :--- | :--- | :---: | :---: | :---: | :--- | :--- | :---: |
| **RSK-01** | Payments & Revenue | **P0** | High | Critical | Public checkout endpoint sets order/invoice to `paid` immediately upon visitor submission without real payment gateway confirmation. Allows unbounded financial spoofing. | Enforce two-phase checkout: create `pending` order, generate provider session/clientSecret, mark `paid` strictly upon cryptographically verified webhook event. | **Identified** |
| **RSK-02** | Ingress Security | **P0** | High | Critical | Meta webhook contains hardcoded backdoor bypass (`meta_chall_44`) and permits unsigned POST payloads when `META_APP_SECRET` is unset. Allows remote conversation forgery. | Remove backdoor string, mandate signature verification in production, reject unsigned events. | **Identified** |
| **RSK-03** | Ingress Security | **P0** | Medium | High | Stripe & Twilio webhooks fall back to hardcoded test secret or skip verification when secrets are missing. | Enforce signature validation in production. Return HTTP 403 on invalid/missing signatures. | **Identified** |
| **RSK-04** | Data Persistence & Multi-Tenancy | **P0** | High | Critical | Application queries in-memory global state rather than normalized PostgreSQL tables with Row-Level Security (RLS). High risk of tenant data bleed and memory exhaustion. | Migrate CRM and transaction queries to direct PostgreSQL client with RLS session variables (`withTenantTransaction`). | **Identified** |
| **RSK-05** | Session & CSRF Security | **P0** | High | High | CSRF tokens are not returned in `/api/auth/session` response payload; client cookie reading fails under strict browser contexts. | Return `csrfToken` in auth session endpoint; support `/api/auth/csrf` refresh; enforce token validation on all mutating methods. | **Identified** |
| **RSK-06** | Outbound SSRF & Workflow Safety | **P1** | Medium | High | Workflow HTTP request action must be protected against DNS rebinding, private subnet IP resolution, and cloud metadata access. | Enforce IP address resolution validation, protocol allowlisting, and size/timeout caps. | **Mitigated in Engine, Needs API Gateway Audit** |
| **RSK-07** | Queue Durability | **P1** | Medium | High | If Redis connection drops, application falls back to memory queue. In production, un-acknowledged jobs would be lost on process restart. | Throw fatal startup exception in production if Redis is unreachable unless explicitly overridden. | **Enforced in Code, Verified** |
| **RSK-08** | Architecture Maintainability | **P1** | High | Medium | Single monolithic file (`apps/api/server.mjs`) exceeding 8,800 lines of code creates elevated defect rates and makes reviews hazardous. | Decompose into modular controllers, services, repositories, and routes under `apps/api/src/`. | **In Progress** |
| **RSK-09** | Distributed Abuse & Rate Limiting | **P1** | Medium | Medium | Rate limiter uses local in-memory Map; easily bypassed in multi-pod deployments or via spoofed IP headers. | Implement Redis-backed token bucket or atomic counter with validated reverse proxy IP extraction. | **Identified** |
| **RSK-10** | Design Drift | **P2** | Medium | Medium | UI requires alignment with user's selected Figma reference (`Atlas-Desktop-Control-Center`). | Map tokens, components, and layout frames from Figma into the React web application. | **Scheduled Phase 4** |
